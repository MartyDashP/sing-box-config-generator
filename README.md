# sing-box VLESS + Reality — генератор конфигурации

Скрипт для автоматической генерации и обновления конфигурации **sing-box** с протоколом **VLESS + Reality**.

Поддерживает несколько пользователей, два режима работы (полная перегенерация / инкрементальное обновление) и формирует готовые ссылки для подключения.

> Сделано агентом. Без участия человека. Как без ГМО, только ещё и без Homo sapiens.

## Возможности

- Генерация `config.json` для sing-box
- Поддержка нескольких пользователей
- Два режима:
  - `full` — полная перегенерация ключей и UUID
  - `update` — добавление только новых пользователей (старые UUID и ключи сохраняются)
- Автоматическая проверка конфига (`sing-box check`) и перезапуск сервиса
- Генерация готовых `vless://` ссылок
- Поддержка флага в названии профиля (эмодзи)
- Бэкап предыдущего конфига

## Требования

- `sing-box` в `$PATH`
- Права root (скрипт пишет в `/etc/sing-box/` и перезапускает сервис)
- Bash 4+

## Структура файлов

| Файл | Описание |
|------|----------|
| `generate_singbox_config.sh` | Основной скрипт |
| `base.conf` | Входной файл с настройками и списком пользователей |
| `output.conf` | Результирующий файл (ключи, UUID, ссылки). Используется в режиме `update` |

## Формат `base.conf`

```ini
domain=example.ru
log_level=debug
server_name=MyServer
flag=🇷🇺

# Опционально (по умолчанию 127.0.0.1:8443)
# handshake_server=127.0.0.1
# handshake_port=8443

# Пользователи (по одному имени на строку)
alice
bob
charlie
```

### Параметры

| Параметр | Обязательный | Описание |
|----------|--------------|----------|
| `domain` | да | Домен / SNI |
| `log_level` | нет | Уровень логирования (`debug`, `info`, `warn` и т.д.) |
| `server_name` | нет | Название сервера (используется в имени профиля) |
| `flag` | нет | Флаг (эмодзи), добавляется в начало названия профиля |
| `handshake_server` | нет | Сервер для Reality handshake |
| `handshake_port` | нет | Порт для Reality handshake |

## Использование

```bash
chmod +x generate_singbox_config.sh

# Полная перегенерация (новые ключи + новые UUID всем)
./generate_singbox_config.sh full

# Обновление (добавляет только новых пользователей)
./generate_singbox_config.sh update
```

## Режимы работы

### `full`
- Генерирует новую пару Reality-ключей
- Генерирует новый Short ID
- Создаёт новые UUID для всех пользователей
- Полностью перезаписывает конфигурацию

### `update`
- Сохраняет существующие Reality-ключи и Short ID
- Для пользователей, которые уже были в `output.conf` — использует старые UUID
- Для новых пользователей — генерирует новые UUID
- Пользователи, удалённые из `base.conf`, исключаются из конфига

## Пример ссылки

```
vless://xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx@example.ru:443?encryption=none&flow=xtls-rprx-vision&security=reality&sni=example.ru&fp=chrome&pbk=...&sid=...&type=tcp#🇷🇺 MyServer-alice
```

## Структура `output.conf`

Файл содержит:

- Общие параметры и ключи (для режима `update`)
- UUID каждого пользователя в формате `USER_<имя>=<uuid>`
- Готовые ссылки для подключения

## Примечания

- Перед записью нового конфига создаётся бэкап: `/root/config.json.bak`
- Скрипт проверяет конфигурацию через `sing-box check` перед перезапуском
- Handshake по умолчанию направлен на `127.0.0.1:8443` (как в оригинальном примере)
- Имена пользователей не должны содержать символ `=`
